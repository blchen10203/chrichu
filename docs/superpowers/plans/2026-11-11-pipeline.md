# Reachdle Data Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the published ufcstats CSVs into `web/data/fighters.json`, `web/data/metrics.json` and a report the owner uses to pick which metrics ship.

**Architecture:** Four small Python modules in `pipeline/`: string parsers, per-fighter metric derivation, the metric table with its statistics, and a `build.py` that downloads, checks and writes. A fifth script drafts the roster. Nothing is written unless the whole build succeeds.

**Tech Stack:** Python 3.13, standard library only at runtime. pytest for tests.

**Spec:** `docs/superpowers/specs/2026-11-10-reachdle-design.md` (sections 5, 11.1, 11.2, 12).

This is plan 1 of 4, following the spec's build order (section 14). Later plans: engine with Daily and Infinite; Survival; weekly Action.

## Global Constraints

- Runtime uses the Python standard library only. pytest is the only dev dependency.
- On this Windows machine the command is `py`, not `python`. Run everything from the repo root.
- Read only these four files from `https://raw.githubusercontent.com/Greco1899/scrape_ufc_stats/main/`: `ufc_fighter_tott.csv`, `ufc_event_details.csv`, `ufc_fight_results.csv`, `ufc_fight_stats.csv`. Never contact ufcstats.com. Do not copy that project's code (GPL-3.0).
- `build.py` writes no file unless every check passed.
- Spec values: step = 0.4 standard deviations; a shipped metric needs at least 30 eligible fighters; rate and percentage metrics need at least 5 tracked fights; `min_per_td` needs at least 3 takedowns; `finish_rate` needs at least 5 wins; log metrics need a value of at least 1.
- Commit directly to `main`. Do not commit any fighter headshot (the repo is public; spec section 14).
- Out of scope: `images.py`, the weekly Action, and its two guards (15% change, fewer than 150 fighters). Those belong to the Action plan.

## What the real data showed (checked 2026-11-11)

- Every fight in the dataset is at a UFC event, so "UFC fights" is simply every fight row. No event filter is needed.
- Some fighters are spelled differently in the fighter file and in fight rows ("Waldo Cortes-Acosta" vs "Waldo Cortes Acosta"). So `roster.csv` `name` is the **fight-row spelling**, and `ufcstats_id` picks the fighter-file row.
- Nine names belong to two fighters each (for example Bruno Silva, Jean Silva, Michael McDonald).
- Text fields carry stray spaces: `EVENT` and `METHOD` in the results file end with a space. Strip every field before use.
- 21 early bouts have stat rows that are entirely blank. Three events are missing from the events file, so their fights have no date.
- Formats: height `6' 4"`, reach `84"`, missing value `--`, birth date `Jul 19, 1987`, event date `November 07, 2026`, strikes `42 of 48`, control time `3:37`, knockdowns `0.0`, round label `Round 1`, outcome `W/L` (first fighter in `BOUT` won), `L/W`, `D/D`, `NC/NC`.

## Decisions the spec left open

- `age` in `fighters.json` is the age on the day of the build. It exists so the metric has a spread and a slider range; the site still recomputes it from `dob` (spec 5.3).
- A log metric's `snap` is `null` in `metrics.json`. The site snaps those to 2 significant figures. (`web/lib/engine/types.ts` currently types `snap` as a number; the engine plan changes it.)
- Standard deviation is the population form (`statistics.pstdev`).
- A slider's upper end is capped at 100 for percentage metrics, so an axis never reads 108%.
- "At least 5 tracked fights" applies to metrics built from fight statistics. Metrics built from results alone (`win_pct`, `avg_fight_len`) need 5 fights of any kind.
- `win_pct` leaves no-contests out of the denominator.
- A doctor's stoppage counts as a KO/TKO win.

## Review Focus

Each line is pinned by a test in the task named.

1. A roster name that does not match the fight-row spelling must stop the build and name the fighter, not ship a fighter with zero fights. (Task 4)
2. A bout with blank stat rows must count as a fight but not as a tracked fight, and must not crash the parsers. (Tasks 1, 2)
3. Old time formats (`No Time Limit`, `1 Rnd + OT (12-3)`) must give the right fight length. (Task 1)
4. A failed download or failed check must leave the existing JSON files untouched. (Task 4)
5. A fighter with missing height, reach or birth date must be kept, with only that metric left out. (Task 2)

## File Structure

| File | Responsibility |
|---|---|
| `pipeline/parse.py` | Turn one dataset string into a number, date or id. No I/O. |
| `pipeline/derive.py` | Group fight rows by fighter; compute one fighter's eligible metrics. |
| `pipeline/metrics.py` | The candidate metric table (spec 5.3); spread statistics, slider range, rounding. |
| `pipeline/build.py` | Download, match roster, run checks, write the two JSON files and the report. |
| `pipeline/draft_roster.py` | One-off helper that writes a first-draft `roster.csv` for the owner to trim. |
| `pipeline/conftest.py` | Empty. Its presence puts `pipeline/` on the import path for pytest. |
| `pipeline/requirements-dev.txt` | `pytest` |
| `pipeline/tests/data/*.csv` | Four tiny sample CSVs in the real format. |

Modules import each other by bare name (`import parse`), which works both for `py pipeline/build.py` and for pytest.

- [ ] **Step 4: Implement `summarize`, `slider` and `round_value`**

- `summarize`: `sd` is `statistics.pstdev` of the values (of their `log10` for a log scale). `step` is `0.4 * sd`. `min`, `median`, `max` are in real units.
- `slider`: take pool minimum and maximum, pad each side by 10% of the range. For a log scale do this in `log10` space and convert back. Then floor at 0 (at 1 for a log scale) and, when `unit == "%"`, cap at 100.
- `round_value`: a linear metric rounds to the nearest multiple of its snap; a log metric rounds to 1 decimal place. Finish with `round(x, 4)` to clear float noise.

### Task 3: Derive one fighter's metrics

**Files:**
- Create: `pipeline/derive.py`
- Test: `pipeline/tests/test_derive.py`

**Interfaces:**
- Consumes: `parse` (Task 1).
- Produces:
  - `fights_by_fighter(results: list[dict], stats: list[dict], events: list[dict]) -> dict[str, list[dict]]`. Key is the fighter's name as written in `BOUT`. Each fight is `{"date": str | None, "outcome": "W" | "L" | "D" | "NC", "method": str, "seconds": int, "tracked": bool, "mine": totals, "theirs": totals}`. `totals` is a dict of ints summed over the fight's rounds: `kd, sig, sig_att, td, td_att, sub, ctrl, head, body, leg` (`ctrl` in seconds; `head`, `body`, `leg` are landed counts).
  - `metrics_for(fights: list[dict], height: float | None, reach: float | None, dob: str | None, deceased: bool, today: datetime.date) -> dict[str, float]`. Unrounded. Contains a key only when the fighter is eligible for it.

import pytest

import derive

EVENTS = [{"EVENT": "UFC 1", "URL": "", "DATE": "January 10, 2020", "LOCATION": ""}]
TODAY = date(2026, 11, 11)


def result(bout, outcome="W/L", method="KO/TKO ", event="UFC 1 "):
    return {"EVENT": event, "BOUT": bout, "OUTCOME": outcome, "METHOD": method,
            "ROUND": "1", "TIME": "5:00", "TIME FORMAT": "3 Rnd (5-5-5)"}


def stat(bout, fighter, sig="10 of 20", td="1 of 2", ctrl="1:00", event="UFC 1"):
    return {"EVENT": event, "BOUT": bout, "ROUND": "Round 1", "FIGHTER": fighter, "KD": "1.0",
            "SIG.STR.": sig, "TD": td, "SUB.ATT": "1.0", "CTRL": ctrl,
            "HEAD": "6 of 12", "BODY": "3 of 5", "LEG": "1 of 3"}


def career(n, **mine):
    """n wins for 'A One' over distinct opponents, each 5:00, as fight dicts."""
    results, stats = [], []
    for i in range(n):
        bout = f"A One vs. Opp {i}"
        results.append(result(bout))
        stats += [stat(bout, "A One", **mine), stat(bout, f"Opp {i}", sig="5 of 10", td="0 of 1")]
    return derive.fights_by_fighter(results, stats, EVENTS).get("A One", [])

        [result("A One vs. B Two")],

- [ ] **Step 3: Implement `fights_by_fighter`**

Join results to stats on `(EVENT stripped, BOUT with whitespace collapsed)`. `BOUT.split(" vs. ")` gives the two names; the first letter pair of `OUTCOME` belongs to them in order. A fighter's stat rows are those whose stripped `FIGHTER` equals their name; `tracked` is true when there is at least one. `theirs` is the other fighter's totals in the same bout. `date` comes from the events file by stripped `EVENT`, else `None`.

- [ ] **Step 4: Implement `metrics_for`**

"Tracked" sums use tracked fights only. `minutes` = tracked seconds / 60. A metric is left out when its rule fails or its denominator is 0.

| Metric | Value | Needs |
|---|---|---|
| `height`, `reach` | as given | not `None` |
| `age` | whole years from `dob` to `today` | `dob`, not deceased |
| `debut_age` | whole years from `dob` to the earliest dated fight | `dob`, one dated fight |
| `slpm` / `sapm` | my / their `sig` per minute | 5 tracked fights |
| `str_acc` | 100 × my `sig` / `sig_att` | 5 tracked fights |
| `str_def` | 100 × (1 − their `sig` / `sig_att`) | 5 tracked fights |
| `head_pct`, `body_pct`, `leg_pct` | 100 × that target / (`head` + `body` + `leg`) | 5 tracked fights |
| `td_avg`, `sub_avg` | 15 × my `td` (or `sub`) / minutes | 5 tracked fights |
| `td_acc` | 100 × my `td` / `td_att` | 5 tracked fights |
| `td_def` | 100 × (1 − their `td` / `td_att`) | 5 tracked fights |
| `td_per_fight` | my `td` / tracked fights | 5 tracked fights |
| `min_per_td` | minutes / my `td` | 3 takedowns, value ≥ 1 |
| `career_sig`, `knockdowns` | my `sig`, my `kd` | `career_sig` ≥ 1 |
| `control_time` | my `ctrl` / 60 | value ≥ 1 |
| `ufc_fights`, `ufc_wins` | all fights, all `W` | none |
| `win_pct` | 100 × wins / fights that are not `NC` | 5 fights |
| `ko_wins` | wins with method `KO/TKO` or `TKO - Doctor's Stoppage` | none |
| `sub_wins` | wins with method `Submission` | none |
| `finish_rate` | 100 × (`ko_wins` + `sub_wins`) / wins | 5 wins |
| `cage_time` | seconds of all fights / 60 | value ≥ 1 |
| `avg_fight_len` | `cage_time` / fights | 5 fights |

- [ ] **Step 4: Implement `read_csvs` and `build`**

`read_csvs` opens `base_url + name + ".csv"` with `urllib.request.urlopen` (it handles `file://` too), decodes UTF-8 and parses with `csv.DictReader`.

`build`, in order, raising `BuildError` with a message that names the fighter or metric:

1. Stop if the roster is empty, or a `name` appears twice in it.
2. For each roster row: stop if no fighter-file row has that id (`parse.fighter_id(URL)`); stop if any *other* fighter-file row has the same stripped name as the roster `name`; stop if `fights_by_fighter` has no fights under that `name`.
3. Height, reach and birth date come from the fighter-file row; fights come from the roster `name`. `id` is `parse.slug(name)`. `hasImage` is whether `image_dir / f"{id}.png"` exists. `trackedFights` counts tracked fights. `deceased` is `row["deceased"] == "1"`.
4. Compute `metrics_for` for everyone, then `summarize` and `slider` for every candidate over its eligible fighters.
5. Stop if a `ship` id is not in `CANDIDATES`, has fewer than `min_eligible` eligible fighters, or has step 0.
6. Fighters output: roster order; `metrics` holds shipped metrics only, each through `round_value`.
7. Metrics output: ship order; keys `id, label, unit, round, scale, snap, min, max, step`; `step` is the `shipped["step"]` override when present; `min`, `max`, `step` rounded to 4 decimals.
8. Report: a title line with `today` and the fighter count, then one aligned line per candidate: id, n, min, median, max, sd, step, and `SHIP` when shipped.

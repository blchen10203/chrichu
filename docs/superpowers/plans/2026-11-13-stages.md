# Reachdle Interactive Stages Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bar chart with a gesture suited to each stat, and remove every sign of a launch date.

**Architecture:**
- A stage table (`web/components/stages/index.tsx`) maps each stat to a stage kind. A `Stage` component renders the matching stage, falling back to `BarStage`.
- `RoundShell` and `Reveal` render `<Stage>` instead of choosing a stage inline.
- Each new stage is one component taking the existing `StageProps`. Dial and tachometer share pure arc geometry in `web/lib/arc.ts`.
- The engine, scoring, storage and modes do not change.

**Tech Stack:** Next.js 16 (static export), React 19, TypeScript, Tailwind 4, inline SVG, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-13-stages-design.md` (approved). It builds on `docs/superpowers/specs/2026-11-10-reachdle-design.md`.

## Global Constraints

- Work in `web/` and run npm commands from `web/`. Commit directly to `main`.
- Never start a dev server yourself. `npm run e2e` starts its own, and Next.js allows only one dev server per project folder, so a stray one makes Playwright hang.
- Every stage takes `StageProps = { metric, refValue, value, onChange?, actual? }` from `@/components/BarStage`.
  - With `onChange` set, the stage is interactive.
  - With `actual` set, the stage shows the reveal: no controls, and the true value drawn as a dashed white outline with `data-testid="true-value"`.
- Map values to pictures only through `toFraction`, `fromFraction`, `snapValue` and `nudge` from `@/lib/engine/scale`.
  - Each picture spans `toFraction` 0 to 1.
  - Drags clamp at the ends and never wrap.
- Each stage has exactly one focusable `role="slider"`, carrying:
  - `aria-label="Your estimate"`;
  - `aria-valuemin={fromFraction(metric, 0)}`, `aria-valuemax={fromFraction(metric, 1)}`, `aria-valuenow={value}`;
  - `aria-valuetext={formatValue(metric, value)}`.
- Keys: ArrowUp and ArrowRight call `nudge(+1)`, ArrowDown and ArrowLeft call `nudge(-1)`.
- No digits may appear inside a stage while guessing. The blue value appears only in `FighterRows`.
- The plot element has `touch-none` (CSS `touch-action: none`). Drags use pointer capture.
- Touch targets are at least 44 px. The layout works from 360 to 430 px wide.
- Use colour tokens or `currentColor` for colours, never hex. The blue reference is drawn left of or behind the red estimate.
- Choose a stage by returning an element from a `switch`. Never assign a component to a variable, which the lint rule `react-hooks/static-components` forbids.

## Review Focus

1. Tapping a stack past its maximum must stop at the maximum, not grow forever. (Task 2 e2e)
2. A dial or tachometer drag through the dead gap at the bottom must land on the nearer end and never wrap from max to min. (Task 3 unit tests)
3. A tank press that turns into a drag must stop filling. The level must not creep after the finger moves. (Task 6 e2e)
4. ArrowUp must change the value on every stage. The Daily, tabs and Survival tests rely on it. (every stage spec, through `expectGuessing`)
5. Dragging on any stage must not scroll the page. (every stage spec checks `touch-action: none`; the owner checks by hand on a phone)

### Task 3: Arc geometry and the dial

**Files:**
- Create: `web/lib/arc.ts`, `web/lib/arc.test.ts`, `web/components/stages/DialStage.tsx`, `web/e2e/dial.spec.ts`
- Modify: `web/components/stages/index.tsx` (`win_pct` and `finish_rate` map to `"dial"`)

**Interfaces:**
- Produces, in `web/lib/arc.ts`:
  - `fractionAt(dx: number, dy: number, sweepDeg: number): number`. `dx, dy` is the pointer's offset from the centre in screen coordinates, with y pointing down. The result is a fraction from 0 to 1.
  - `pointAt(t: number, sweepDeg: number): { dx: number; dy: number }` returns the unit vector at fraction `t`.
- The arc is symmetric about the vertical. It starts at the bottom left and runs clockwise over the top to the bottom right, with the gap centred at the bottom.

- [ ] **Step 3: Implement `arc.ts`**

Use the compass angle `c = atan2(dx, -dy)` in degrees, normalised to 0–360, with `start = 180 + (360 - sweep) / 2`. Then:
- `d = (c - start) mod 360`.
- If `d <= sweep`, return `d / sweep`.
- Otherwise the point is in the gap: return `1` if `d - sweep < 360 - d`, else `0`.

`pointAt` inverts this: `c = start + t * sweep`, `dx = sin c`, `dy = -cos c`.
